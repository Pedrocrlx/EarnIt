# Project Context: EarnIt (AGENTS.md)

This document serves as the absolute single source of truth for AI agents operating within the development workflow of **EarnIt**. It defines the core problem, system architecture, tech stack boundaries, feature scope, and team responsibility protocols.

---

## 1. Executive Summary & Core Value
* **Product Definition:** EarnIt is a web application for allowance management based on performance and gamification. It is explicitly an educational and motivational tool, not a banking or financial solution.
* **Academic Context:** Developed within the *Project II – Web Programming* course.
* **The Core Loop:** Parent creates tasks -> Child completes tasks -> Parent approves tasks -> Child earns progress toward a visual goal.
* **Primary Target Audience:** Children aged 7 to 10 years old (and their parents). Devices are frequently shared, requiring seamless user-switching profiles.

## 3. Core Security & Authentication Engine

* **Parent Authentication:** Secure stateless JWT (JSON Web Tokens) issued asynchronously by FastAPI upon successful email/password login.
* **Token Storage:** Handled via secure, HTTP-only cookies to mitigate Cross-Site Scripting (XSS) token leakage.
* **Child Authentication:** Hassle-free, direct access to the child dashboard from a shared family device without a password.
* **Dashboard Switching Perimeter:** Transitioning from the Child to the Parent dashboard requires entering a parent-defined PIN. 
  * The PIN must be salted and hashed in the database (never stored as raw text).
  * Verification must occur via an asynchronous backend endpoint (`/api/v1/auth/verify-pin`) utilizing a non-blocking hashing library (such as `passlib` with `bcrypt` or `argon2-cffi` configured for async execution).

## 4. Functional Scope (MVP v1 Matrix)

Agents must strictly build inside the MVP boundary. Do not implement features listed as out of scope.

### In Scope (MVP)
* **Parent Capabilities:**
  * Register and login (Email + Password).
  * Create and manage multiple child profiles linked to 1 parent account (Data model structured for future SaaS plans).
  * Create tasks with: Title, description, reward value (€), expiry time countdown, and task type.
  * View pending task completions submitted by children.
  * Approve or reject tasks (with optional rejection notes or one-click Batch Approval).
  * Define 1 visual goal per child (Name, target price, image).
  * View per-child balance sheets and transaction history.
* **Child Capabilities:**
  * Password-free dashboard access via shared devices.
  * View available tasks for the day with expiry countdown tags.
  * Mark tasks complete + upload a photo as proof.
  * View current balance and historical earnings.
* **Gamification Engines:**
  * **Streak Bonus:** Completing the same task $X$ days in a row grants extra coins or a badge.
  * **Puzzle Reveal:** The child's goal image is split into 10 pieces, uncovered progressively ($10\%$ per milestone achieved).
  * **Balance Toggle:** A frontend switch transforming numeric Euro values into real-world equivalent items (e.g., e.g., "= 3 Ice Creams").

### Task Types Separation
1. **Duty:** Regular household responsibilities (e.g., make the bed). Not Paid. Exist to build responsibility habits without monetizing every interaction.
2. **Extra Task:** Optional tasks beyond routine rules. Paid. Only Extra Tasks generate monetary rewards.

### Strictly OUT OF SCOPE for MVP
* Mobile Push Notifications (use visual countdowns instead).
* Tinder-style swipe approval interface.
* Avatar XP systems, virtual outfits, or interactive 3D coin jars.
* Home screen widgets, offline synchronization modes, or actual real-money payment gateway/subscription integrations.
* Multiple simultaneous goals per individual child.
